Help Center

TuneBridge keeps your local music, playlists, devices, gear, and listening history in one place. Start with your library, then add a device when you are ready to sync.

Four steps to get set up
1
Choose your music folder
Pick it during setup, or change it any time in Settings → Library.
2
Scan the library
TuneBridge reads your tracks, albums, tags, and artwork so it knows what you have.
3
Add your players in Gear
Only needed if you want to sync music to a device. Skip this if you are listening on this Mac.
4
Build or import playlists
Create them here, import existing ones, or use Sync Music to copy tracks and playlists to a device together.
Library & playlists
Library
The folder TuneBridge watches. After you add, rename, or retag music, use the scan button in the sidebar so the app refreshes its view. Your library root is set in Settings → Library.
Playlists
Create playlists in TuneBridge, download them as .m3u files, or copy them straight to a connected device. Imports read .m3u and .m3u8. When an import cannot match every song, TuneBridge keeps those tracks visible so you can map them by hand.
Devices & audio gear
Devices & Sync
Add each player in Gear, then set its mount path, music folder, playlist folder, and path prefix. Sync Music uses those settings to plan what needs copying. Before a large sync, check the review step. It shows what will be added, removed, and whether the device has enough space.
Gear & PEQ
Gear holds devices, IEMs, headphones, frequency response links, and PEQ profiles. PEQ files can be copied to a device when it has a PEQ folder configured. For best graph results, use a squig.link measurement URL and keep one clear profile per tuning you actually use.
Insights & backup
Insights
Reads tags and audio analysis to show library health, genre spread, sonic shape, play history, and gear fit. Run Analyse Library for deeper results. If tags change later, use Rescan so the charts and missing tag lists catch up.
Care & Backup
Backups cover playlists, devices, IEMs, settings, and app data. Take one before changing your library folder, moving to a new Mac, or making big device changes. App data lives at ~/Library/Application Support/TuneBridge.
Key locations
Music library
The folder TuneBridge scans. Configurable in Settings → Library. Expected file structure: Artist/Album/NN. Title.flac. Artwork is cached separately and does not need to live in the music folder.
App data
Playlists, devices, IEMs, settings, and cached artwork are stored separately from your music. When running as the Mac app, data lives at ~/Library/Application Support/TuneBridge/. In dev mode it uses the data/ folder next to app.py.
Playlist exports
When you export or sync a playlist, TuneBridge writes a .m3u file to the device. The exact folder depends on the device profile. Each line in the file is a path to one track, relative to the playlist file or the device root.
How playlist paths work

Each line in a .m3u file points from the playlist file to a music file. The right format depends on where the device expects the playlist and where the music lives. If a playlist opens on a device but tracks will not play, the path prefix in the device profile is usually the cause.

No prefix
Playlist and music share the same root
Music/Artist/Album/01. Track Title.flac
Prefix ..
Playlist is one folder deeper than music
../Music/Artist/Album/01. Track Title.flac
Export folders by device
Poweramp / FiiO Player
Playlists write to Playlists/ at the SD card root. Paths inside use no prefix: Music/Artist/Album/track.flac. Poweramp displays the filename as the playlist name, so rename inside the app if needed.
AP80 Pro Max
Playlists write to playlist_data/ at the SD card root, which is one level below where Music lives. Paths use the .. prefix: ../Music/Artist/Album/track.flac. Important: the device must create playlist_data/ itself first. Save a dummy playlist natively on the AP80, then let TuneBridge take over.
HiBy OS
Playlists write to HiByMusic/Playlist/. Paths use no prefix and are relative to the storage root. Applies to HiBy R5, R6, and similar players.

Still stuck? Open the device in Gear, check the Export folder and Prefix fields, then try exporting a single-track playlist to see the exact path TuneBridge writes.

TuneBridge Privacy Policy

TuneBridge runs entirely on your Mac. No data is ever sent to the
developer. TuneBridge does not collect, track, or transmit any
personal information.

WHAT WE COLLECT
Nothing. There is no analytics, no telemetry, and no usage tracking
of any kind.

NETWORK REQUESTS
TuneBridge fetches data from third-party services to enrich your
library. All requests are outbound only: TuneBridge pulls data from
these services and does not share your personal information with them.

Automatic (no setup required):
  • iTunes Search API: fetches album artwork and release metadata
  • MusicBrainz: fetches album and artist metadata
  • LrcLib: fetches song lyrics

Optional (only when you add an API key in Settings):
  • Last.fm: fetches artist images and biography
  • Fanart.tv: fetches high-resolution artist artwork

Gear section only (only when you use the IEM library):
  • squig.link: fetches headphone frequency response measurements

No personal data (your name, email, location, or listening history)
is included in any of these requests. Queries contain only the track
title, artist name, or album name needed to find the right result.

THIRD-PARTY SERVICES
Each service listed above has its own privacy policy. TuneBridge has
no control over how they handle requests made to their servers.

DATA STORAGE
All your data (playlists, settings, listening history) is stored
locally on this device in:
  ~/Library/Application Support/TuneBridge/
